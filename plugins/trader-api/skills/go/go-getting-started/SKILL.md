# Getting started with an APIMatic-generated Go SDK

> Controller types are `{Resource}Api` and are reached through methods on the client —
> `client.{Resource}Api()`. The `Api` suffix is a generator setting, so **confirm it** from the
> `*_api.go` files in the root package.

This is the **SDK-specific** reference and grounding layer, and the entry into the companion `go-*` skills.
These SDKs are produced by **APIMATIC v3.0** and depend on the shared runtime
`github.com/apimatic/go-core-runtime`. For the general patterns that apply to *any* such SDK (client
setup, auth, calling endpoints, models, error handling, retries, testing), see the companion
API-agnostic skills: `go-client-initialization`, `go-authentication`, `go-calling-endpoints`,
`go-models`, `go-error-handling`, `go-configuration-resilience`, `go-testing`.

**The source and these companion skills are complementary — load both.** The generated source is
authoritative for the SDK's *surface* (function signatures, struct fields, enums, which error type an
operation returns); the companion skills are the *usage layer* on top — the right way to call each piece
and the gotchas a signature can't show. Reading the source doesn't remove the need to load the skill for
that step, so at each step below load the companion *and* confirm names against the source.

> **Before writing any integration code, clone the SDK source** (one command, in the *SDK source* section
> below) and read it to confirm every signature, struct, enum, and error type as you go. Do **not** vendor
> or copy the SDK source into your module, and do **not** fetch GitHub files ad hoc — clone once, then
> grep the local copy. It's a throwaway reference: delete it when the integration is done.

The table above is **orientation, not a copy-paste recipe** — it gives you the names and facts (package
name, client/config constructors, the auth *pattern*, the environments), while the actual integration
code comes from the companion skills. Load each one as you reach its step (see **Integration workflow**
below) and confirm its types against the cloned source.

## Package layout

APIMatic Go SDKs split public types across a few packages under the module root:

- **root package** (`traderapi`) — `client.go` (the `ClientInterface`, `NewClient`, controller accessors),
  `configuration.go` (`Configuration`, `CreateConfiguration*`, the `With...` options, `Environment`/`Server`
  constants), `default_configuration.go`, one `*_controller.go` per API resource group (and `*Manager.go`
  for OAuth managers), the per-scheme `*_authentication.go` files, `base_controller.go`, `core.go`,
  `tests_base.go`, and `*_test.go`.
- `models/` — request/response structs, `enums.go`, union types, and `utilities.go`. **This is where
  struct field names, optionality, and enum values live.**
- `errors/` — typed `{Operation}`/`{Name}` error structs (when the API documents error responses).

Go does not import child packages transitively — import each package you reference. If a type isn't
found, open its file in the cloned source and copy the `package` declaration at the top for the import.

## Install

```bash
go get github.com/context-plugins/trader-api-go-sdk@main
```

```go
import (
    "github.com/context-plugins/trader-api-go-sdk"            // root package — client + configuration
    "github.com/context-plugins/trader-api-go-sdk/models"     // request/response types, enums, unions
)
```

> The import path matches the module declared in the SDK's `go.mod`. `go get github.com/context-plugins/trader-api-go-sdk@main` also
> pulls in `go-core-runtime` transitively.

## SDK source — clone it first; don't fetch files ad hoc

You will constantly need to confirm real function signatures, struct field names, enums, and error types,
and the **only reliable way** is to read the SDK source. Clone it once, up front — before writing
integration code — into your **system temp directory** (outside your module), then read and grep the
local copy. It is a read-only, throwaway reference — never add a `replace` directive pointing at it:

```bash
# Linux / macOS:
git clone --depth 1 --branch main https://github.com/context-plugins/trader-api-go-sdk /tmp/trader-api-go-src
```

```powershell
# Windows (PowerShell):
git clone --depth 1 --branch main https://github.com/context-plugins/trader-api-go-sdk "$env:TEMP\trader-api-go-src"
```

Then confirm the SDK shape **only** from that local clone:

- **Don't fetch GitHub files one at a time** — `…/blob/…` pages return HTML and guessed paths fail.
  Clone once and read locally. Only if `git` is unavailable, fetch a **raw** URL of the form
  `https://raw.githubusercontent.com/{owner}/{repo}/{branch}/…` (never a `…/blob/…` page).

Layout — grep the clone here first:

- `configuration.go` — `Configuration`, the `With...` options, `Environment`/`Server` constants, and the
  `CreateConfigurationFromEnvironment` env-var names.
- `client.go` — the `ClientInterface`, `NewClient`, and the controller accessor methods.
- `*_controller.go` — operation functions and their `(models.ApiResponse[T], error)` signatures.
- `models/` — request/response structs, `enums.go`, unions; **this is where field names live**.
- `errors/` — typed error structs (when generated).
- `README.md` and `doc/` — a generated, human-readable index: `doc/client.md`, `doc/auth/*.md`,
  `doc/controllers/*.md`, `doc/models/*.md`, `doc/http-configuration.md`, `doc/retry-configuration.md`,
  `doc/api-response.md`. **Grep `doc/` first** — it is the fastest way to find an operation, its
  parameters, and a usage snippet, then open the `.go` file for the exact signature.

Clean up when done:

```bash
rm -rf /tmp/trader-api-go-src                               # Linux / macOS
```
```powershell
Remove-Item -Recurse -Force "$env:TEMP\trader-api-go-src"   # Windows
```

## Integration workflow — load the companion skill at each step

Before you write the code for each step, load the named companion skill — even if you've already read the
relevant source. Each step calls out the trap the signature hides (in *parens*).

1. **Client construction** — load **go-client-initialization** before you call
   `traderapi.NewClient(traderapi.CreateConfiguration(...))`. (*The signature won't tell you:* you don't construct
   the client with options directly — you build a `Configuration` with `With...` options and pass it to
   `NewClient`; the client is read-only after construction and meant to be long-lived and shared.)
2. **Authentication** — load **go-authentication** before you set credentials. (*The signature won't tell
   you:* each scheme is a **typed credentials struct** — `New{Scheme}Credentials(...)` set via a
   `With{Scheme}Credentials(...)` configuration option — not a single token string; load secrets from the
   environment.)
3. **Calling an endpoint** — load **go-calling-endpoints** before the first
   `client.{Resource}Api().{Operation}(ctx, ...)` call. (*The signature won't tell you:* `ctx` is
   always first; multi-parameter operations bundle their parameters into an `{Operation}Input` struct; the
   return is `models.ApiResponse[T]`, not the bare value.)
4. **Models** — load **go-models** the moment a request/response field isn't a plain string or number.
   (*The signature won't tell you:* optional fields are `*T` pointers; enums are typed `int` or `string`
   constants; union fields are built with a `{Type}Container.From{Variant}(...)` helper and read with
   `As{Variant}()`; unknown JSON is preserved in `AdditionalProperties`, not dropped.)
5. **Error handling** — load **go-error-handling** before you check an error return. (*The signature won't
   tell you:* a non-2xx response is returned as the `error` value; it embeds `https.ApiError` (status,
   body, headers) and documented errors are typed structs in `errors/` — a missing type assertion loses
   that detail.)
6. **Configuration & resilience** — load **go-configuration-resilience** when you tune retries, timeouts,
   transport, or the base URL. (*The signature won't tell you:* retries are **disabled by default**
   (`maxRetryAttempts` = 0) and only `GET`/`PUT` are retried even when enabled; timeout and transport live
   on `HttpConfiguration`.)
7. **Testing** — load **go-testing** before you stub the SDK. (*The signature won't tell you:* the test
   seam is the HTTP transport — inject a custom `http.RoundTripper` via `WithTransport`, or point the SDK
   at an `httptest.Server`; no SDK mocking helpers are provided for consumers.)
