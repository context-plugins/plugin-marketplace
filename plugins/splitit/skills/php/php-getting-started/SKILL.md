# Getting started with an APIMatic-generated PHP SDK

> API accessor classes live under `src/Apis/`, one `{Resource}Api` class per resource group. **Confirm
> the exact accessor method name and style on the client** from the client class source before writing a
> call — it isn't safe to assume.

> `SplititClient` is the SDK's client class — **read the real name** from the `*Client.php` file in
> `src/` (it is derived from the API title with APIMatic's own casing, so do not guess it from the
> API name). `SplititClientBuilder` sits beside it.

This is the **SDK-specific** reference and grounding layer, and the entry into the companion `php-*`
skills. These SDKs are produced by **APIMATIC v3.0** (`This file was automatically generated by
APIMATIC v3.0` header on every file) and depend on the shared runtime packages `apimatic/core`,
`apimatic/core-interfaces`, and `apimatic/unirest-php`. For the general patterns that apply to *any* such
SDK (client setup, auth, calling endpoints, models, error handling, retries, testing), see the companion
API-agnostic skills: `php-client-initialization`, `php-authentication`, `php-calling-endpoints`,
`php-models`, `php-error-handling`, `php-configuration-resilience`, `php-testing`.

**The source and these companion skills are complementary — load both.** The generated source is
authoritative for the SDK's *surface* (method signatures, model fields, enums, which exception an
operation throws); the companion skills are the *usage layer* on top — the right way to call each piece
and the gotchas a signature can't show. Reading the source doesn't remove the need to load the skill for
that step, so at each step below load the companion *and* confirm names against the source.

> **Before writing any integration code, get the SDK source and read it** (the *SDK source* section
> below) to confirm every method, model field, enum, and exception type as you go. Do **not** fetch
> GitHub blob pages ad hoc — read the local copy (the generated SDK ships its own `doc/` and `src/`). It
> is a read-only reference.

## SDK identity

| | |
| --- | --- |
| API | `splitit` |
| Generator | APIMATIC v3.0 (header on every `.php` file) |
| Runtime dependencies | `apimatic/core`, `apimatic/core-interfaces`, `apimatic/unirest-php` (HTTP call builder, auth managers, retries, response handling) — pulled in transitively |
| Composer package | from `composer.json` `name` — e.g. `apimatic-sdks/multiauthsample`, `apimatic-sdks/apimaticcalculator` (the published id varies per SDK) |
| Root namespace | from `composer.json` `autoload.psr-4` — the API title concatenated + `Lib`, e.g. `MultiAuthSampleLib\`, `APIMATICCalculatorLib\` (maps to `src/`) |
| Install | `composer require apimatic-sdks/splititwebapiv3:dev-main` |
| Client class | `SplititClient` — read the real name from the `*Client.php` file in `src/`; implements `ConfigurationInterface`; a factory for API accessors + holder of config |
| Client builder | `SplititClientBuilder` — `::init()->...->build()` (the only intended way to construct the client) |
| Auth | each scheme set on the builder via a `{Scheme}CredentialsBuilder::init(...)` — see **php-authentication** |
| Environments | an `Environment` class of string `public const`s in the root namespace — read `Environment.php` for the real member names |
| Return type | each operation returns the **typed result directly** (a model, a primitive like `float`/`string`, an array) — there is **no** response wrapper |
| Base exception | `SplititLib\Exceptions\ApiException` (extends `\Exception`) |
| PHP version | `^7.2 || ^8.0` (per `composer.json` `require.php`); also requires `ext-json`, `ext-curl` |

The table above is **orientation, not a copy-paste recipe** — it gives you the names and facts (package
id, namespace, client/builder, the auth *pattern*, the environments), while the actual integration code
comes from the companion skills. Load each one as you reach its step (see **Integration workflow** below)
and confirm its types against the source.

## Package layout (under `src/`, PSR-4 from the root namespace)

- **root** (`SplititLib\`) — `SplititClient.php`, `SplititClientBuilder.php`, `ConfigurationInterface.php`,
  `ConfigurationDefaults.php`, `Environment.php`, `Server.php`, `ApiHelper.php`.
- `Apis/` — one `{Resource}Api` per API resource group, plus `BaseApi`. **This is where operation
  method signatures live.**
- `Models/` — request/response data classes, enums (e.g. `OperationTypeEnum`), and polymorphic model
  classes. **Field names, optionality, and enum values live here.**
- `Models/Builders/` — one `{Model}Builder` per model — **the recommended way to construct models**.
- `Authentication/` — per-scheme `{Scheme}CredentialsBuilder`, `{Scheme}Credentials`, `{Scheme}Manager`.
- `Http/` — `HttpRequest`, `HttpResponse`, `HttpContext`, `HttpMethod`, `HttpCallBack`.
- `Exceptions/` — `ApiException` (base) plus per-operation typed subclasses when the API documents an
  error model (e.g. `OAuthProviderException`).
- `Proxy/`, `Utils/` — proxy builder and internal helpers.

## Install

```bash
# Add the SDK as a VCS repository, then require it:
composer config repositories.splitit-php-sdk vcs https://github.com/context-plugins/splitit-php-sdk
composer require apimatic-sdks/splititwebapiv3:dev-main
```

> Running outside an existing Composer project? `composer require` needs a `composer.json` to add to —
> run `composer init --no-interaction` first (or any equivalent project-init step) if one isn't present.

```php
require_once 'vendor/autoload.php';   // Composer PSR-4 autoloader — no manual requires
```

> The package name (`apimatic-sdks/splititwebapiv3`) is declared in the SDK's `composer.json`. `composer require`
> also pulls in `apimatic/core` and friends.

## SDK source — read it first; don't fetch files ad hoc

You will constantly need to confirm real method signatures, model field names, enums, and exception
types, and the **only reliable way** is to read the SDK source. The generated SDK ships its own
human-readable `doc/` index *and* `src/` — read those locally rather than fetching GitHub blob pages one
at a time (they return HTML and guessed paths fail). For a published SDK, clone the repo once into a
throwaway location and grep the local copy:

```bash
# Linux / macOS:
git clone --depth 1 --branch main https://github.com/context-plugins/splitit-php-sdk /tmp/splitit-php-src
```
```powershell
# Windows (PowerShell):
git clone --depth 1 --branch main https://github.com/context-plugins/splitit-php-sdk "$env:TEMP\splitit-php-src"
```

Layout — **grep `doc/` first**, it is the fastest way to find an operation, its parameters, and a usage
snippet; then open the matching `src/` file for the exact signature:

- `doc/client.md` — the full builder-parameter table (auth, environment, timeout, retry settings) and a
  construction snippet. `composer.json` — package id, namespace, PHP version, dependencies.
- `doc/auth/*.md` — one per auth scheme with credential fields and a snippet.
- `doc/controllers/*.md` — every operation with signature, parameter table, and example; mirrors
  `src/Apis/*Api.php` (the doc folder keeps its `controllers` name even where `src/` uses `Apis/`).
- `doc/models/*.md` (+ `doc/models/containers/*.md` for unions) — model fields and a builder example;
  mirrors `src/Models/` and `src/Models/Builders/`.
- `doc/api-exception.md`, `doc/http-request.md`, `doc/http-response.md` — the error/HTTP types.
- There is **no** `http-configuration.md`, `retry-configuration.md`, or `api-response.md` doc — retry and
  HTTP settings are documented inline in `doc/client.md`, and operations return the typed value directly.

Clean up a clone when done:

```bash
rm -rf /tmp/splitit-php-src                               # Linux / macOS
```
```powershell
Remove-Item -Recurse -Force "$env:TEMP\splitit-php-src"   # Windows
```

## Integration workflow — load the companion skill at each step

Before you write the code for each step, load the named companion skill — even if you've already read the
relevant source. Each step calls out the trap the signature hides (in *parens*).

1. **Client construction** — load **php-client-initialization** before you call
   `SplititClientBuilder::init()->...->build()`. (*The signature won't tell you:* you don't `new` the client
   with an options object — you fluently configure a `SplititClientBuilder` and call `->build()`; the
   resulting client is effectively immutable, so build it once and reuse it.)
2. **Authentication** — load **php-authentication** before you set credentials. (*The signature won't tell
   you:* each scheme is a **`{Scheme}CredentialsBuilder::init(...)`** passed to a matching builder method —
   not a single token string; OAuth grants fetch tokens lazily on first call; load secrets from the
   environment.)
3. **Calling an endpoint** — load **php-calling-endpoints** before the first
   `$client->get{Resource}Api()->{operation}(...)` call. (*The signature won't tell you:*
   multi-parameter operations take a single associative **`array $options`** with string keys; the method
   returns the typed result directly and **throws** `ApiException` on a non-2xx instead of returning a
   wrapper.)
4. **Models** — load **php-models** the moment a request/response field isn't a plain string or number.
   (*The signature won't tell you:* build models with `{Model}Builder::init(requiredArgs)->optional(...)
   ->build()`; enums are PHP **class constants** with a `checkValue` validator, not native `enum`s; union
   (oneOf/anyOf) values are passed as the concrete model or raw primitive directly; unknown JSON is kept
   via `addAdditionalProperty`/`findAdditionalProperty`, not dropped.)
5. **Error handling** — load **php-error-handling** before you write a `try/catch`. (*The signature won't
   tell you:* a non-2xx throws `ApiException` (or a typed subclass) carrying `getHttpResponse()` →
   `getStatusCode()`/`getHeaders()`/`getRawBody()` and `getHttpRequest()`; a documented error model
   throws a typed `{Name}Exception` subclass instead.)
6. **Configuration & resilience** — load **php-configuration-resilience** when you tune retries, timeout,
   proxy, or the base URL. (*The signature won't tell you:* retries are **disabled by default**
   (`enableRetries=false`, `numberOfRetries=0`) and, when enabled, only `GET`/`PUT` are retried; all of
   this is set on the *builder*.)
7. **Testing** — load **php-testing** before you stub the SDK. (*The signature won't tell you:* the test
   seam is the HTTP layer — register an `HttpCallBack`/`CallbackCatcher` and/or point the SDK at a mock
   server via the `Environment` base URL; PHPUnit is the project's framework — match it.)
