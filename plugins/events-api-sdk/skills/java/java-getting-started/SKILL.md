# Getting started with an APIMatic-generated Java SDK

This is the **SDK-specific** reference and grounding layer, and the entry into the companion `java-*`
skills. These SDKs are produced by **APIMATIC v3.0** (every generated file carries a
`This file was automatically generated by APIMATIC v3.0` header) and depend on shared runtime
packages: `io.apimatic:core`, `io.apimatic:core-interfaces`, and `io.apimatic:okhttp-client-adapter`.
For the general patterns that apply to *any* such SDK (client setup, auth, calling endpoints, models,
error handling, retries, testing), see the companion skills: `java-client-initialization`,
`java-authentication`, `java-calling-endpoints`, `java-models`, `java-error-handling`,
`java-configuration-resilience`, `java-testing`.

**The source and these companion skills are complementary — load both.** The generated source is
authoritative for the SDK's *surface* (class names, method signatures, enum constants, which exception
type an operation declares); the companion skills are the *usage layer* on top — the right way to call
each piece and the gotchas a signature can't show. Reading the source doesn't remove the need to load
the skill for that step, so at each step below load the companion *and* confirm names against the source.

> **Before writing any integration code, clone the SDK source** (one command, in the *SDK source*
> section below) and read it to confirm every class name, builder method, enum constant, and exception
> type as you go. Do **not** copy the SDK source into your project, and do **not** fetch GitHub files
> ad hoc — clone once, then grep the local copy. It's a throwaway reference: delete it when the
> integration is done.

## Package layout

APIMatic Java SDKs split public types across sub-packages under the root package (`com.m1password.events`):

- **root package** — `EventsAPIClient` (the gateway class), `Configuration` (interface), `Environment`,
  `Server`, `ApiHelper`, `CompatibilityFactoryImpl`.
- `com.m1password.events.authentication/` — one `{Scheme}Model` (the builder/data holder), `{Scheme}Credentials`
  (read interface), and `{Scheme}Manager` (handles wire injection) per auth scheme the API uses.
- `com.m1password.events.controllers/` — `BaseController` plus one `{Resource}Controller` per API resource group.
  **Controller accessors live on the client**: `client.get{Resource}Controller()`.
- `com.m1password.events.exceptions/` — `ApiException` base class plus per-operation `{Name}Exception` subclasses
  (when the API documents typed error responses).
- `com.m1password.events.models/` — request/response POJOs extending `BaseModel` (Jackson `@JsonGetter`/
  `@JsonSetter`), Java `enum` types with custom JSON (un)marshalling, and `containers/` for oneOf/anyOf
  union types.
- `com.m1password.events.http/client/` — `HttpClientConfiguration`, `ReadonlyHttpClientConfiguration`,
  `HttpCallback` (request/response logging seam), `HttpContext`, `HttpProxyConfiguration`.
- `com.m1password.events.http/request/` — `HttpMethod`, `HttpRequest`.
- `com.m1password.events.http/response/` — `HttpResponse`, `HttpStringResponse`.

## Maven / Gradle install

### Maven (`pom.xml`)

```xml
<repositories>
  <repository><id>jitpack.io</id><url>https://jitpack.io</url></repository>
</repositories>
<dependency>
    <groupId>com.github.context-plugins</groupId>
    <artifactId>events-api-java</artifactId>
    <version>main-SNAPSHOT</version>
</dependency>
```

The `io.apimatic` runtime packages (`core`, `core-interfaces`, `okhttp-client-adapter`) are declared
as transitive dependencies in the SDK's own `pom.xml` — they are pulled automatically. Confirm the
exact version ranges in the SDK's `pom.xml`.

### Gradle (`build.gradle`)

```groovy
repositories { maven { url 'https://jitpack.io' } }
implementation 'com.github.context-plugins:events-api-java:main-SNAPSHOT'
```

Or Kotlin DSL (`build.gradle.kts`):

```kotlin
repositories { maven("https://jitpack.io") }
implementation("com.github.context-plugins:events-api-java:main-SNAPSHOT")
```

> JitPack builds the SDK from GitHub on first request; the `io.apimatic` runtime packages resolve
> transitively from the SDK's own `pom.xml`.

## SDK source — clone it first; don't fetch files ad hoc

You will constantly need to confirm real class names, builder methods, enum constants, and exception
types, and the **only reliable way** is to read the SDK source. Clone it once, up front — before writing
integration code — into your **system temp directory** (outside your project), then read and grep the
local copy. It is a read-only, throwaway reference:

```bash
# Linux / macOS:
git clone --depth 1 --branch main https://github.com/context-plugins/events-api-java /tmp/events-api-java-src
```

```powershell
# Windows (PowerShell):
git clone --depth 1 --branch main https://github.com/context-plugins/events-api-java "$env:TEMP\events-api-java-src"
```

Then confirm the SDK shape **only** from that local clone:

- **Don't fetch GitHub files one at a time** — `…/blob/…` pages return HTML and guessed paths fail.
  Clone once and read locally. Only if `git` is unavailable, fetch a **raw** URL of the form
  `https://raw.githubusercontent.com/{owner}/{repo}/{branch}/…` (never a `…/blob/…` page).

Layout — grep the clone here first:

- `pom.xml` — `groupId`, `artifactId`, `version`, and the exact runtime dependency version ranges.
- `EventsAPIClient.java` — builder methods, controller accessors (`get{Resource}Controller()`), `shutdown()`.
- `Configuration.java` — the `Configuration` interface (environment, port, auth credential getters).
- `Environment.java` — the `Environment` enum constants and the default environment.
- `controllers/*.java` — operation method signatures, declared exceptions, and `{Op}Input` types.
- `models/` — POJO fields/builders, enum constants, `containers/` union factory methods.
- `exceptions/` — `ApiException` plus any typed `{Name}Exception` subclasses and their payload fields.
- `README.md` and `doc/` — generated human-readable docs: `doc/client.md`, `doc/auth/*.md`,
  `doc/controllers/*.md`, `doc/models/*.md`, `doc/http-client-configuration.md`,
  `doc/http-client-configuration-builder.md`. **Read `doc/` first** — it's the fastest way to find
  an operation, its parameters, and a usage example.

Clean up when done:

```bash
rm -rf /tmp/events-api-java-src                               # Linux / macOS
```
```powershell
Remove-Item -Recurse -Force "$env:TEMP\events-api-java-src"   # Windows
```

## Integration workflow — load the companion skill at each step

Before you write the code for each step, load the named companion skill — even if you've already read
the relevant source. Each step calls out the trap the signature hides (in *parens*).

1. **Client construction** — load **java-client-initialization** before you call
   `new EventsAPIClient.Builder()...build()`. (*The signature won't tell you:* there is no public
   constructor — you must use the inner `Builder` class; `httpClientConfig` is set via a lambda, not a
   config object; the client is immutable and thread-safe after `build()` and must be shared, not
   recreated per request.)
2. **Authentication** — load **java-authentication** before you set credentials. (*The signature won't
   tell you:* each scheme requires its own `{Scheme}Model.Builder(requiredArgs...).optField(x).build()`
   call passed to the client builder; secrets must come from the environment, never hardcoded; OAuth
   grant flows that need a token exchange have additional steps beyond the initial builder call.)
3. **Calling an endpoint** — load **java-calling-endpoints** before the first controller call.
   (*The signature won't tell you:* every operation has both a synchronous form declaring
   `throws ApiException, IOException` and a `CompletableFuture<T>` async form; multi-parameter
   operations bundle their arguments into a `{Op}Input` built with its own `.Builder(required...)
   .optional(x).build()` pattern.)
4. **Models** — load **java-models** the moment a request/response field isn't a plain `String` or
   `double`. (*The signature won't tell you:* required POJO fields go in the Builder constructor;
   optional fields are set via fluent builder setters and are `null`/`@JsonInclude(NON_NULL)` when
   absent; enums are Java `enum` types with custom `@JsonCreator`/`@JsonValue` and a `fromString` /
   `fromInteger` lookup; oneOf/anyOf union types use static `from{Variant}(...)` factory methods.)
5. **Error handling** — load **java-error-handling** before you write a `try/catch`. (*The signature
   won't tell you:* synchronous operations declare both `ApiException` and `IOException`; typed
   exception subclasses in `exceptions/` extend `ApiException` and add Jackson-annotated payload
   fields accessible via getters; `getResponseCode()` on `ApiException` returns the HTTP status code;
   `getHttpContext()` gives the full request/response context.)
6. **Configuration & resilience** — load **java-configuration-resilience** when you tune retries,
   timeouts, the base URL, or transport. (*The signature won't tell you:* retries are **off by
   default** — `numberOfRetries` defaults to `0`; even when enabled, only `GET` and `PUT` are retried;
   all tuning goes through the `httpClientConfig` lambda on the builder, not a separate config object.)
7. **Testing** — load **java-testing** before you write tests. (*The signature won't tell you:* the
   test seam is an `HttpCallback` implementation injected via `.httpCallback(...)` on the builder;
   the generated `HttpCallbackCatcher` captures the last `HttpRequest` and `HttpResponse`; no OkHttp
   mock adapter ships for consumers — either use a real test server or intercept via the callback.)
