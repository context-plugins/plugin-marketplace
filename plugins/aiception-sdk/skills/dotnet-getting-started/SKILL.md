# Getting started with an APIMatic-generated C#/.NET SDK

This is the **SDK-specific** reference and grounding layer, and the entry into the companion `dotnet-*`
skills. These SDKs are produced by **APIMATIC v3.0** (every generated file carries a
`// This file was automatically generated by APIMATIC v3.0` header) and depend on the shared runtime
NuGet package **`APIMatic.Core`**. For the general patterns that apply to *any* such SDK (client setup,
auth, calling endpoints, models, error handling, retries, testing), see the companion API-agnostic
skills: `dotnet-client-initialization`, `dotnet-authentication`, `dotnet-calling-endpoints`,
`dotnet-models`, `dotnet-error-handling`, `dotnet-configuration-resilience`, `dotnet-testing`.

**The source and these companion skills are complementary — load both.** The generated source is
authoritative for the SDK's *surface* (class names, method signatures, model fields, enums, which
exception an operation throws); the companion skills are the *usage layer* on top — the right way to call
each piece and the gotchas a signature can't show. Reading the source doesn't remove the need to load the
skill for that step, so at each step below load the companion *and* confirm names against the source.

> **Before writing any integration code, clone the SDK source** (one command, in the *SDK source* section
> below) and read it to confirm every class, signature, model, enum, and exception type as you go. It is a
> throwaway read-only reference — do **not** copy it into your project. Delete it when the integration is
> done.

| --- | --- |

| Client | `AIceptionInteractiveClient` (e.g. `MultiAuthSampleClient`) — a `sealed` factory-for-controllers + config holder |

The table above is **orientation, not a copy-paste recipe** — it gives you the names and facts (package,
namespace, client/builder, the auth *pattern*, the environments), while the actual integration code comes
from the companion skills. Load each one as you reach its step (see **Integration workflow** below) and
confirm its types against the cloned source.

## Package layout

APIMatic .NET SDKs put everything under one root namespace `AIceptionInteractive.Standard`:

- **root** — `AIceptionInteractiveClient.cs` (the client + its nested `Builder` class), `Environment.cs` and `Server.cs`
  enums, `IConfiguration.cs`.
- `Controllers/` — one `{Resource}Controller` (sometimes named `{Resource}Api`) per API resource group,
  plus `BaseController`. **Operation signatures live here.**
- `Models/` — request/response classes (extending `BaseModel`), C# enums, and `Models/Containers/` for
  oneOf/anyOf union types. **Field names, optionality, and enum values live here.**
- `Authentication/` — one `{Scheme}Model` + `{Scheme}Manager` + `I{Scheme}Credentials` per auth scheme.
- `Exceptions/` — `ApiException` (base) plus per-operation `{Name}Exception` subclasses.
- `Http/` — `Http/Client/` (`HttpClientConfiguration`, `HttpCallback`, `HttpContext`), `Http/Request/`
  (`HttpRequest`), `Http/Response/` (`HttpResponse`, `HttpStringResponse`, and `ApiResponse<T>` when the
  SDK returns the full response wrapper).
- `Utilities/` — `ApiHelper`/`CoreHelper` JSON helpers, `CompatibilityFactory`.

## Install

```bash
# Clone the SDK and add a project reference to its .csproj:
git clone --branch main https://github.com/context-plugins/aiception-interactive-csharp-sdk
dotnet add reference aiception-interactive-csharp-sdk/AIceptionInteractive.Standard/AIceptionInteractive.Standard.csproj
```

```csharp
using AIceptionInteractive.Standard;                 // client + Builder + Environment enum
using AIceptionInteractive.Standard.Models;          // request/response types, enums, unions
using AIceptionInteractive.Standard.Authentication;  // {Scheme}Model credentials
using AIceptionInteractive.Standard.Exceptions;      // ApiException + typed subclasses
```

> The project reference pulls in `APIMatic.Core` and `Newtonsoft.Json` transitively. Do **not** run
> build/restore commands as part of analysis — just read the source.

## SDK source — clone it first; don't fetch files ad hoc

You will constantly need to confirm real class names, method signatures, model fields, enums, and
exception types, and the **only reliable way** is to read the SDK source. Clone it once, up front — before
writing integration code — into your **system temp directory** (outside your project), then read and grep
the local copy:

```bash
# Linux / macOS:
git clone --depth 1 --branch main https://github.com/context-plugins/aiception-interactive-csharp-sdk /tmp/aiception-dotnet-src
```

```powershell
# Windows (PowerShell):
git clone --depth 1 --branch main https://github.com/context-plugins/aiception-interactive-csharp-sdk "$env:TEMP\aiception-dotnet-src"
```

Then confirm the SDK shape **only** from that local clone:

- **Don't fetch GitHub files one at a time** — `…/blob/…` pages return HTML and guessed paths fail. Clone
  once and read locally. Only if `git` is unavailable, fetch a **raw** URL of the form
  `https://raw.githubusercontent.com/{owner}/{repo}/{branch}/…` (never a `…/blob/…` page).

Layout — grep the clone here first:

- `AIceptionInteractiveClient.cs` — the client, its nested `Builder`, the controller accessor properties, the
  `Environment`→base-URL map, and `CreateFromEnvironment` (the env-var names it reads).
- `Controllers/*.cs` (or `Apis/*.cs`) — operations, their parameters, and `Task<T>` / `Task<ApiResponse<T>>`
  return types; the `.ErrorCase(...)` registrations name the typed exception per status.
- `Models/` (+ `Models/Containers/`) — request/response classes, enums, unions; **field names live here**.
- `Authentication/` — the `{Scheme}Model` builders and credential interfaces.
- `Exceptions/` — `ApiException` and typed subclasses.
- `README.md` and `doc/` — a generated, human-readable index: `doc/client.md`, `doc/auth/*.md`,
  `doc/controllers/*.md`, `doc/models/*.md`, `doc/http-client-configuration.md`, `doc/api-exception.md`.
  **Grep `doc/` first** — it is the fastest way to find an operation, its parameters, and a usage snippet,
  then open the `.cs` file for the exact signature.

Clean up when done:

```bash
rm -rf /tmp/aiception-dotnet-src                               # Linux / macOS
```
```powershell
Remove-Item -Recurse -Force "$env:TEMP\aiception-dotnet-src"   # Windows
```

## Integration workflow — load the companion skill at each step

Before you write the code for each step, load the named companion skill — even if you've already read the
relevant source. Each step calls out the trap the signature hides (in *parens*).

1. **Client construction** — load **dotnet-client-initialization** before you call
   `new AIceptionInteractiveClient.Builder()...Build()`. (*The signature won't tell you:* every setter returns the
   `Builder` for chaining and the client is **immutable** after `.Build()`; the client is a heavyweight,
   thread-safe, long-lived object — construct one and reuse it, don't `new` it per request. Use
   `.ToBuilder()` to derive a modified copy.)
2. **Authentication** — load **dotnet-authentication** before you set credentials. (*The signature won't
   tell you:* each scheme is a **`{Scheme}Model`** built with `new {Scheme}Model.Builder(...).Build()` and
   registered via `.{Scheme}Credentials(...)` on the client builder — not a single token string; load
   secrets from configuration, and a partially-filled scheme is silently dropped at `Build()`.)
3. **Calling an endpoint** — load **dotnet-calling-endpoints** before the first
   `await client.{Resource}Controller.{Operation}Async(...)` call. (*The signature won't tell you:* you get
   the controller from a **property** on the client; prefer the `…Async` overload; many-parameter
   operations bundle their params into a single `{Operation}Input` model; the result is the bare `T`
   unless the SDK was generated to return `ApiResponse<T>`.)
4. **Models** — load **dotnet-models** the moment a request/response field isn't a plain string or number.
   (*The signature won't tell you:* optional fields are C# nullables tagged `NullValueHandling.Ignore`;
   enums are real C# enums with `[EnumMember]` wire values; oneOf/anyOf unions are **abstract classes**
   built with `{Union}.From{Variant}(...)` factories and read with `.Match<T>(...)` — `new` doesn't work;
   unknown JSON is preserved in `AdditionalProperties`, not dropped.)
5. **Error handling** — load **dotnet-error-handling** before you write a `try`/`catch`. (*The signature
   won't tell you:* a non-2xx throws `ApiException` (or a registered typed subclass), whose
   `HttpContext.Response` carries the status/headers/body; which subclass is thrown is decided by the
   operation's `.ErrorCase("<status>", …)` map, not by the method signature.)
6. **Configuration & resilience** — load **dotnet-configuration-resilience** when you tune retries,
   timeout, transport, or the base URL. (*The signature won't tell you:* retries default to
   `NumberOfRetries = 0` (**off**) and, when enabled, only retry `GET`/`PUT` and a fixed status-code set;
   everything is set through `.HttpClientConfig(Action<HttpClientConfiguration.Builder>)`.)
7. **Testing** — load **dotnet-testing** before you stub the SDK. (*The signature won't tell you:* the test
   seam is the **`HttpClient`** — pass your own via `.HttpClientConfig(c => c.HttpClientInstance(...))`
   backed by a fake `HttpMessageHandler`; there are no consumer-facing SDK mocking helpers.)
